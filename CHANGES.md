# Changelog

What changed in BdREN VAULT, newest first. Entries are numbered in the order they were made; each one
says what changed and why. To install a new version, see [Updating](README.md#updating).

## 24 Nov 2026

Entries 118-150.

118. **Paging fixed** - Next / Previous under the Session Log list no longer also opened a session and jumped back to page 1 (the pager buttons now use their own attribute and stop the click there). After a page change the list scrolls back to its top if it was out of sight.
119. **Smoother moves between screens** - the whole page no longer cross-fades on top of the content's own fade (that made it blink twice); the old screen stays until the new one is ready, then only the content fades up. The side menu and top bar stay put, the side menu keeps its scroll position from screen to screen, and the cross-page transition listener now loads in the page head so a skipped transition no longer shows an error in the browser console.
120. **Fixed retention for login records** - the Session Log keeps two years of logins and commands. Authentication Audit keeps accepted logins for two years and rejected ones for six months. A daily clean-up deletes older rows (in small slices, so FreeRADIUS keeps writing). The Session Log no longer follows Settings > "Keep logs and backup files for", which still covers Activity Logs and saved configurations.
121. **Forever means nothing is deleted** - with Settings > "Keep logs and backup files for" set to Forever (do not delete), the daily clean-up no longer deletes Session Log or Authentication Audit records either. The two-year / six-month periods for them apply only when a period is chosen there. The settings page explains this. Also removed a browser console error after changing screens (a skipped cross-page transition) and an unused import.
122. **One retention period for every log** - Settings > "Keep logs and backup files for" now offers Forever, 12, 24 or 48 months, and the chosen period applies to all logs alike: Activity Logs, saved configuration versions (the newest of each device always stays), Session Log and accepted logins in Authentication Audit. 12 months deletes what is older than 12 months, and so on; Forever deletes nothing at all, rejected logins included. With a period chosen, rejected logins are deleted after six months. A server that had 1, 3 or 6 months set now has 12 (it keeps more, never less). This replaces the separate two-year / six-month periods of items 119 and 120.
123. **Easier to read** - the green OK and amber Warning text on light badges is darker so it reads clearly on its tinted background, the blue button gradient no longer fades to a light cyan behind white text, and small labels, tags and table headings that were 10 to 11.5 px are now 12 px.
124. **Easier on phones and clearer when empty** - on phones every button, chip, field and list control is at least 40 px tall (small square buttons 40 x 40, checkboxes 20 px); the sidebar section titles are a brighter grey; an empty Device Inventory, Backup Jobs, RADIUS Users or NAS list now shows a button for the next step (Add device, Back up all devices, Add user, Add NAS; not shown to a Viewer for operator actions), and an empty Configuration Backups page links to Device Inventory; while a list loads it shows grey placeholder rows in its place, so the page no longer jumps when the list arrives (no pulsing with reduced motion).
125. **A more informative Dashboard** - a new "Needs attention" card lists the devices offline right now and the devices whose last backup failed, with the error, and says how many wait for an automatic retry (each row opens the device; "All clear" when nothing is wrong). "Recent configuration changes" lists the newest backups that saved a new configuration. Administrators also see "Device logins, last 24 hours" from RADIUS: attempts, accepted, rejected, users, devices and logins outside a user's allowed devices (read at most once a minute).
126. **No repeated numbers** - Device Inventory no longer has a KPI row above the list: its totals were the same as the filter chips (All / Online / Offline / Backup failed) and the Dashboard. On the Dashboard, "Backup completed" and "Backup not completed" are one card, "Last backup OK" (with failed and not-run counts); the new "Last backup run" card shows when the newest run started, how many devices were ok or failed and how long it took; "Online" shows the average ping time. System health has one Disk card (was two), drops "Last successful backup" and "Failures, last 24 h" (shown by the cards above and the 14-day chart), and adds how long logs are kept and, for administrators, whether the Session Log receiver is running.
127. **Repository tidied** - README has a table of contents, a page-by-page guide to the portal, a ports and services table, the installer options (`APP_DIR`, `SVC_USER`) and a data and retention section. This changelog is grouped by date with clean numbering. The Docker files were removed: they were not used or documented and left out FreeRADIUS, the syslog receiver and nginx, so `deploy/install.sh` is the one supported way to install.
128. **Design polish** - statistic tiles show their icon in a small coloured badge instead of a faint picture behind the text, and lay out evenly (three per row, six on wide screens, never 5 + 1); every card heading has a small accent mark; the Dashboard shows a status pill next to Refresh ("All systems normal", or how many devices need attention, with how many are online); long System health values are cut to two lines.
129. **Calmer sign-in page** - the VAULT name and BdREN logo no longer shimmer, and the footer shows the year and reads "Backup today, ensure tomorrow". The sign-in form itself is unchanged.
130. **Session Log: commit and save are labelled as such** - `commit` (Huawei VRP 8, Juniper), `save` (Huawei), `write` / `write memory` / `copy running-config startup-config` (Cisco) and `execute cfg save` (FortiGate) were shown as "+ add" like a new configuration line. They now show as "✓ commit" or "✓ save" in blue; they still count as changes.
    - Cisco: commands typed with `do` in configuration mode are judged by the command after it, so `do wr` shows as "✓ save" and `do show ...` / `do ping ...` count as view commands, not changes (for new log lines). "Configured from ... by ..." (leaving configuration mode) shows as "✓ done" instead of "+ add".
131. **Faster Dashboard** - the uptime chart now gets at most 288 points (one per 5 minutes) instead of every ping sweep (1,440 a day at 60 s), so each 30-second refresh sends about 19 KB instead of 105 KB with 3,000 devices and draws far fewer points; "Backups per day" is one database query instead of 14. The installer turns on HTTP/2 in the nginx site (the page files then load in parallel over one HTTPS connection); if nginx refuses it, the site is left as it was.
132. **Logs of any period** - Authentication Audit and Session Log can show the last 90 days, the last year, or **Custom dates** (a From and a To day, up to three years at once), as far back as System Settings keeps logs. On Authentication Audit the login list now follows the chosen period too (before, it always showed the newest 500 logins).
133. **Session Log order** - in Sessions, By device and By user, sessions still open ("Active") come first, then the newest login first (before: by the time of the last activity).
134. **A logout reported by RADIUS ends the session** - a Session Log session no longer stays "Active" after the user has left when the device's syslog logout message does not reach VAULT: the RADIUS accounting Stop (radacct, sent by devices set up with the Device Setup commands, accounting start-stop) now closes it. Zero-length Stop records from per-command accounting are not counted as logouts, and a Stop for a session already closed by syslog changes nothing.
135. **Device host names in the Session Log** - VAULT keeps the host name each device writes in its syslog messages (Huawei, Juniper, RFC 5424, Fortinet devname) and shows it with the address: "ahsan on Training-Room-AS-04", 10.252.0.149 below it, in Sessions, By device, By user and Devices sending logs. A name set in NAS Clients or Device Inventory still comes first; Cisco writes no host name unless "logging origin-id hostname" is set. Database change: one new column (migration commandlog 0003).
136. **A session that began before the chosen period shows its login time** - a session still going when the period starts (logged in yesterday at 05:23 PM, logged out at 05:33 PM, viewed today at 05:26 PM with "Last 24 hours") showed "Before period" as its start. The Session Log now looks up to 24 hours further back for its login, so it shows 05:23 PM -> 05:33 PM and its length. Sessions that ended before the period are still left out.
137. **Calmer, more professional notification sounds** - the sounds are now short, soft chimes like a system notification (a clear tone with a faint bell overtone and a natural fade) instead of sliding "game" effects: backup finished = two rising notes, saved = one light tap, added = a quick rising pair, deleted = a quick falling pair, finished with failures = two even notes, failed = a lower falling pair. A gentle filter and limiter keep them quiet and free of harsh peaks. The on/off button and the per-kind choices in Settings work as before. Also fixed a browser console error when leaving the Dashboard within two seconds of opening it.
138. **Dashboard without the network animation** - the "Network overview" banner with the moving network picture at the top of the Dashboard is removed (and its styles); the page now starts with the statistic tiles and the "Needs attention" card.
139. **The "log messages were ignored" note goes away when fixed** - Session Log showed "N log messages were ignored because the sender is not on NAS Clients" for ever, even after that address was added to NAS Clients, because the count was never reset. Now the note is shown only while the problem is current: it disappears as soon as the sender is on NAS Clients (address or network), and a day after the last refused message; a new problem after a quiet day starts a new count. Database change: one new column (migration commandlog 0004).
140. **Cisco show commands in the Session Log** - Cisco logs only configuration commands by itself, so show, ping and other commands were missing. Device Setup > Cisco > "Command logging" now ends with a small event manager applet (VAULT-CLI-LOG) that sends every command with the user name, and VAULT lists show / ping / traceroute from it as view commands. Configuration commands still come from the archive log, so they are not counted twice, and end / exit / configure terminal are left out. Tested on an ASR1002 (IOS-XE 3.13, EEM 4.0); needs EEM with the cli event detector and $_cli_username.
141. **Cisco device names and configure terminal** - with "logging origin-id hostname" on the router, VAULT now reads the name Cisco writes in each message (SUST-EDGE-R1) and shows it with the address, like Huawei and Juniper, even when the NAS entry has no name. configure terminal (and enable) from the EEM applet now show as view lines; end, exit and quit are still left out because the archive log already shows them.
142. **Deleted NAS devices leave "Devices sending logs"** - a device deleted from NAS Clients is no longer accepted by the receiver, so it no longer stays in the Session Log list of devices sending logs either. Its past sessions stay in the Session Log.
143. **Add an ignored sender in one click** - the Session Log note "log messages were ignored because the sender is not on NAS Clients" now has a button "Add <address> to NAS Clients". It opens Add NAS with that address filled in; give it a name and vendor and save, and the firewall opens UDP 514 for it.
144. **"What to do" on every Session Log warning** - each warning note (receiver not installed or not running, waiting for the first device, messages ignored, messages dropped) has a "What to do" button that opens the steps to fix it. Under the steps of "messages ignored" (with "Add <address> to NAS Clients") and "messages dropped" is "Done, dismiss": it clears the note, which comes back only with the next such message. The other notes go away by themselves once fixed.
145. **Cisco applet catches view commands only** - Device Setup > Command logging for Cisco now gives the event manager applet the pattern "^(show|ping|traceroute|configure|telnet|ssh|clear|debug|undebug|terminal)" instead of ".*". Configuration commands still come from the archive log (with hidekeys), so nothing is lost, and a password typed in a configuration command is no longer sent in clear text. On a router that has the old applet, enter the applet again with the new event line.
146. **NAS Clients names filled in from syslog** - a NAS Clients entry added without a name (its name is its address) now gets the name the device sends in its syslog (Cisco "logging origin-id hostname", Huawei and Juniper headers), as soon as the device sends a log. The name is kept in one place, NAS Clients, and every page reads it from there: NAS Clients, Session Log, Authentication Audit and user access. A name someone typed is never changed; each automatic name is written to the RADIUS audit log (nas.name). FreeRADIUS uses the name only as a label, so nothing restarts.
147. **RADIUS passwords stored as hashes** - new command `manage.py radius_hash_passwords` turns the RADIUS passwords still stored in clear text into salted SHA-256 (SSHA2-256-Password) without changing them, so nobody needs a new password. `--user NAME` does one user, to test a login on every kind of device first; without it the command needs `RADIUS_PASSWORD_MODE=ssha2` in .env, so that new passwords are hashed too. It cannot be undone, and these users can then log in with PAP only (SSH / Telnet logins use PAP). Each run is written to the RADIUS audit log (user.hash).
148. **RADIUS passwords are always hashed** - the clear-text mode is gone: every RADIUS password VAULT stores is salted SHA-256 (SSHA2-256-Password), and the `RADIUS_PASSWORD_MODE` setting is no longer read. `deploy/install.sh` runs `manage.py radius_hash_passwords --yes`, which converts any password still stored in clear text without changing it. These users log in with PAP, which SSH / Telnet logins on network devices use.
149. **Authentication Audit: From filled in from syslog** - devices that send no Calling-Station-Id with the login request (Huawei switches, for one) showed "-" under From. VAULT now takes that address from the same device's syslog in the Session Log: the same user's login line (Huawei UserAddress=), else the closest command line (Ip=), from 2 minutes before to 10 minutes after the login. An address sent with the RADIUS request still comes first. Needs the device to send its logins to VAULT (Device Setup, step "Command logging").
150. **Menu button in the top bar** - the small arrow next to the VAULT name is gone. The menu button (three lines) now sits at the left of the top bar on every screen size: on a computer it minimises or expands the side menu (remembered in the browser, as before), on phones and tablets it opens the side menu.

## 23 Nov 2026

Entries 103-117.

103. **Device Setup: Huawei NetEngine tab** - copy-ready RADIUS commands for NetEngine 8000 / NE40E and other VRP 8 routers: a radius-server group (original user name, source interface, retransmit/timeout), authentication and accounting schemes in domain default_admin, vty login through AAA and the commit VRP 8 needs. Filled with this server's address and the chosen device's shared secret; marked "check against your firmware".
104. **Authentication Audit page explains itself** - the old "Recent logins 500" box was only the number of rows loaded, not people. The page now has a period choice (last 24 hours, 7 days or 30 days) and shows real totals for it: login attempts, successful (with %), failed, different users and different devices. A new "Failed logins to check" table lists the user + device pairs that failed most often, when they last tried, and the likely cause (wrong password / not allowed on that device, or a username that does not exist in RADIUS). Device logins says it shows the newest 500 matching attempts. radius_init adds an index on radpostauth.authdate so the totals stay fast on large tables.
105. **Command History: who ran which command on which device** - new page RADIUS / AAA > Command History. A new service, vault-syslog (`manage.py syslog_receive`), receives the devices' syslog on UDP 514 and keeps every user action: commands (Huawei SHELL/5/CMDRECORD, Juniper interactive-commands), configuration changes (Cisco archive log config, Juniper commit / change-log, MikroTik "changed by", Fortinet cfgpath), logins, logouts and failed logins, with the user's own address. The page has a 24 h / 7 d / 30 d summary (changes, commands, logins, failed logins, users), search by user / device / address / command, a type filter, CSV export, and a "Devices sending logs" list that shows the last unrecognised message of a device so a new model can be checked. Security: only addresses on NAS Clients are accepted (the firewall sync now also opens UDP 514 for exactly those addresses), at most 200 messages a second per device, and the receiver runs as the `vault` user with only the right to use port 514. Kept as long as the other logs (Settings > Keep logs and backup files for). Device Setup has a new last step, "Command logging", with the syslog commands for every vendor. install.sh installs and starts the receiver; on an existing server run `sudo bash /opt/vault/deploy/enable_syslog.sh` (install.sh does it on update).
106. **Fix: enable_syslog.sh stopped without a message** - when SYSLOG_PORT was not in .env (the normal case), the script ended silently before doing anything, so the Command History receiver was never installed; the same new line also stopped enable_firewall_sync.sh (RADIUS firewall sync). A setting missing from .env now simply means its default (514).
107. **Session Log (was Command History)** - the menu item and page are renamed "Session Log" (RADIUS / AAA > Session Log; the address stays /radius/commands). the page now opens on "Sessions", laid out like the Change Reports page: one card per user with their session count, changes and view commands (bar), failed logins, "Active now" and the last login. Opening a card shows that user's sessions, newest first, on a timeline: device, duration and status, then a log of the session from "Logged in from <address>" through every command in order (changes highlighted) to "Logged out" (or "Still logged in" / "No logout recorded"). A session starts at the RADIUS login (Access-Accept) or the device's own login message and ends at the logout; without a logout it ends after 30 minutes without activity. A user's sessions load when their card is opened; /radius/commands#user=<name> opens that card, and a user name in "All activity" jumps to it. "All activity" keeps the previous flat list. A login or logout that a device reports twice (Huawei SHELL + SSH) is now kept once, and a hidden address (Ip=**) is shown as empty. Device Setup, Huawei: the command logging step is now the three lines that are enough (info-center enable, info-center loghost <server>, info-center source SSH ... informational).
108. **No more of the same list in two places** - Activity Logs > Administrative audit trail is now the one list of every administrative action: the panel's own (devices, backups, settings, panel users, tagged VAULT) and the changes made on the RADIUS pages (users, NAS, unblocks, tagged RADIUS), newest first. Sign-ins, failed sign-ins and sign-outs are no longer repeated there; they stay in User Management > Sign-in history, which the audit trail links to. Authentication Audit drops its "Panel changes" card for a short pointer to the audit trail and keeps device logins, failures and blocked addresses. Session Log's "Failed logins" figure links to Authentication Audit, which has every failed login with its likely cause. Device Inventory's buttons are named like Backup Jobs': "Back up all devices" and "Retry failed devices".
109. **Session Log by device and by user** - the "All activity" tab is gone; the page now has three views of the same sessions, laid out like Change Reports. **Sessions** (the default): one card per login, newest first - "<user> on <device>", the device address and where they came from, the status (Logged out / Active / No logout / Failed login), "Session 2 of 2" when the same user came back to the same device, the changes and view commands, and "10:00 AM → 11:00 AM" with the date and duration; opening the card shows that session's log, with links to all of the user's sessions and to everyone on the device. **By device**: one card per device with its users, sessions, changes and last login; opening it shows "Who logged in" (each user with their changes and sessions) and then every session on that device, newest first: the user, where they came from, how long, and a log from "Logged in" through every command (changes highlighted) to "Logged out". When the same user logs in to the same device again (in at 10:00, out at 11:00, in again at 13:00) that is a new session with its own changes; each shows its time range (10:00 AM → 11:00 AM) and "Session 1 of 2", "Session 2 of 2". **By user**: the same per user, across every device. A user or device name opens the other view (/radius/commands#device=<address> or #user=<name>), and "Changes only" in a card hides the view-only commands. The sessions API takes device=<address>.
110. **Authentication Audit: failed logins as a log** - "Failed logins to check" (the ten user + device pairs that failed most, with a count) is replaced by "Failed logins": every failed login of the chosen period, newest first, one row each - time, user, device (and the station address when recorded) and the likely cause (wrong password / not allowed on this device, or a username that does not exist in RADIUS), with pages and a count. Up to the newest 1,000 are listed.
111. **Failed logins and blocked addresses in one card, with where each login came from** - Authentication Audit's "Failed logins" and "Blocked addresses" cards are one card, "Failed logins & blocked addresses", with two tabs and a count on each. Every login now also records the address it came from (Calling-Station-Id, e.g. the SSH client's IP): `enable_login_log.sh` adds a `callingstationid` column to radpostauth and writes it in the post-auth query (safe to run again on a server already set up). Failed logins and Device logins get a **From** column; an address FreeRADIUS is blocking now is marked **Blocked**, and a private address is marked "Private, never blocked", so it is clear why a guessed name such as root is or is not blocked. Device logins can be searched by that address too. Until the script is run again the card says so and the column stays empty. After updating, run `sudo bash /opt/vault/deploy/radius/enable_login_log.sh` (and `enable_ip_block.sh` if IP blocking is not on yet).
112. **IP blocking and the "Failed logins & blocked addresses" card removed** - the card is gone from Authentication Audit; failed logins are the Rejected rows of Device logins (filter "Rejected"), which also show the device name and the From address. The FreeRADIUS policy that blocked an address for 2 days after an unknown username is removed completely: the Unblock API (`/api/radius/blocks/<id>`), the `IpBlock` model (migration 0007), `enable_ip_block.sh`, the `dbms_ip_block` policy file and `RADIUS_BLOCK_ALLOW_USERS`. On a server that has the old policy, install.sh now runs the new `deploy/radius/disable_ip_block.sh`: it takes the policy out of FreeRADIUS (checks the configuration and puts the old files back if the check fails), restarts FreeRADIUS so no address stays blocked, and then drops the `dbms_ip_block` table. The source address (Calling-Station-Id) is still recorded. To stop password guessing, limit SSH/Telnet on the devices to the management addresses with an ACL.
113. **Session Log shows only real sessions** - refused (failed) logins reported by the devices are no longer cards in Session Log, and the "Failed logins" figure and filter are gone from that page; failed logins are on Authentication Audit (Device logins, "Rejected").
114. **Security: Operators can no longer send a saved device password to a host of their choice** - found in the pre-publish security review. An Operator could change a device's address to their own server (or add a device with another device's saved login) and let the backup log in there, which handed over the saved password and enable secret that only an Administrator may see. Now: the saved-login list and reusing a saved login (Add device, import, "apply to the other devices") are Administrator-only, and an Operator who changes a device's address or SSH port must type its password (and enable secret, when one is saved) again; otherwise the change is refused with a clear message. Administrators work as before. Recommended as well: set `DBMS_ALLOWED_NETWORKS` in .env to the management networks, so backups only connect there.
115. **Session Log: changes read like a diff** - in a session's log every configuration change is marked "+ add" in green, and a change that takes something away (undo, no, delete, deactivate, unset, purge, MikroTik remove) "- remove" in red. View commands look as before.
116. **Session Log on phones** - each login card is laid out in rows on a narrow screen (who on which device, status, bar, counts and from-to time), so the name is no longer cut off and the time no longer covers the counts; in By device / By user the names line wraps, and inside a card the date and time stay readable next to the status.
117. **Session Log: "diagnose" is not a change** - entering Huawei's diagnostic view (`diagnose` typed on its own, or its short forms) only switches mode, like `system-view`, so it is shown as a view command instead of "+ add". Followed by more words it still counts as a change. Migration `commandlog 0002` corrects the actions already recorded.

## 22 Nov 2026 - first version on GitHub

Entries 1-102.

1. **Dashboard "Database file 0 B"** - the code looked for a SQLite file, but the app uses MySQL. The card is now "Database size" and reads data+index size from MySQL (SQLite still supported).
2. **"Backups per day: No backups"** - the query used `ts__date` / `TruncDate`, which on MySQL needs the time-zone tables (otherwise NULL, empty chart). Days are now grouped in Python.
3. **Backups started late** - the old job pinged the *whole* inventory (and resolved DNS one by one) before the first SSH login. Now ping and SSH are a pipeline: each device is queued for SSH the moment it answers. Offline devices never occupy an SSH worker.
4. **Slow dead devices** - a silent SSH device is retried once (was 3x30 s).
5. **"Devices online" graph dips** - ping defaults are now 2 attempts / 1.5 s, and failed hosts get a second round (with a 3 s pause if >40% fail at once).
6. **Day shows no data in the Backups tree** - an UNCHANGED check overwrote the day's `run.json` (SUCCESS). A saved snapshot's record is now kept; `run.json` is written atomically.
7. **Log/DB write can no longer turn a good backup into FAILED** - names are cut to 100 chars (MySQL strict mode), DB errors in `record()` are logged, not raised.
8. **MySQL stability** - `CONN_HEALTH_CHECKS`, connect/read/write timeouts, job progress writes retry after a dropped connection.
9. **Ready to publish** - no password or IP is stored in the code any more: `DBMS_DB_PASSWORD` is required in `.env`, and `DJANGO_ALLOWED_HOSTS` (your public IP/domain) also goes in `.env`.
10. **Code cleanup** - shared helpers instead of copies (`get_json_list`/`get_id_list`/`set_pending_devices`, `_atomic_write_text`), dead `_ensure_enable_mode` and unused imports/variables removed.
11. Default `WORKERS` 5 -> 10. Tests updated/added (65 pass).
    - Upgrade note: Do NOT overwrite your existing `data/` folder (it holds `secret.key`).
    - Upgrade note: After copying, restart the service. Static files were already rebuilt in `staticfiles/`.
12. **RADIUS Admin merged in** - the separate RADIUS panel is now the `apps/radius` app. Administrators get a "RADIUS Admin" drop-down in the side menu (Users, Devices (NAS), Audit). It uses a second database connection (`RADIUS_DB_*` in `.env`) and the normal sign-in of this application. See "RADIUS Admin (merged)" in the README.
13. **"A backup is already running" can no longer get stuck** - a running job writes a heartbeat; a job left behind by a restart or crash is closed after 3 minutes without one (was 24 hours). The Devices page now shows a "Backup running: X of Y devices done" bar for any running job (also after a page refresh, or when the schedule or another user started it) with a **Stop backup** button for operators and administrators. Devices whose SSH session hangs past every timeout are marked failed instead of holding the job open forever.
14. **500 devices in one backup** - "Back up all" runs the whole inventory as one job. Parallel SSH sessions can now be set from 1 to 50 on the Settings page (was effectively 15).
15. **Code cleanup** - no password or server IP is left in `config/settings.py`: `DBMS_DB_PASSWORD` and `DJANGO_ALLOWED_HOSTS` must be set in `.env`. The duplicated database block is one clear `mysql` / `sqlite` switch (`DBMS_DB_ENGINE`, default `mysql`). The Users page Edit / Delete buttons no longer use inline `onclick`, which the Content-Security-Policy blocks. A start-up error in the browser console (`dashTimer`) is fixed. Old log files and a stray file were removed from the source.
16. **New sign-in and first-run setup page** - same navy and indigo as the rest of the application, a short description of the system, a notice after an automatic sign-out for inactivity, dark mode and a phone layout.
17. **RADIUS users per switch** - the user pop-up has "Where this user can log in": all devices, or selected switches only. Network entries cannot be picked one by one. A failed audit-log write no longer hides or repeats the real change. (Storage changed in item 20.)
18. **Review pass: security and tidying**
    - RADIUS shared secrets are no longer sent with the device list; one is fetched only on Show / Copy and the request is audited. A typed secret needs 12+ characters, and the same IP / network cannot be added twice.
    - Optional `RADIUS_PASSWORD_MODE=ssha2` (salted SHA-256 instead of clear-text RADIUS passwords) and `DBMS_REVEAL_PASSWORDS=0`.
    - `DBMS_ALLOWED_NETWORKS` works again as an optional allow-list for SSH and ping targets; `manage.py show_network_policy` no longer crashes.
    - CSV exports neutralise cells that a spreadsheet would run as a formula. Bulk import skips loopback / special-use addresses. Two endpoints answered 500 on malformed input and now answer 400.
    - New `manage.py radius_init`, `deploy/vault.service` and `deploy/nginx-dbms.conf`; the README no longer points at files that do not exist and states Python 3.10+.
    - The RADIUS pop-ups show the database error instead of opening with empty lists.
